# SysMind 项目功能文档

本文档基于当前仓库实现整理，目标是帮助开发、测试和产品快速理解项目定位、核心功能、运行方式与实现边界。

## 1. 项目概述

### 1.1 项目定位

`SysMind` 是一个用于绘制系统关系图、思维结构图和项目规划图的可视化编辑工具。

它的核心特点是：

- 以节点和连线为基础表达复杂关系
- 支持键盘优先的快速编辑
- 支持导入、导出、保存和图片导出
- 支持中英文切换与浅色/深色主题
- 同时支持浏览器运行和 Electron 桌面壳运行

### 1.2 当前形态

当前项目本质上是一个前端单页应用，主要业务逻辑集中在 `src/App.tsx` 中，外层提供：

- Web 运行形态：基于 React + TypeScript + Vite
- 桌面运行形态：基于 Electron 打包
- 静态部署能力：适配 GitHub Pages 等静态托管场景

## 2. 技术与目录结构

### 2.1 技术栈

- 前端框架：React 19
- 语言：TypeScript
- 构建工具：Vite
- 样式方案：Tailwind CSS + 自定义 CSS
- 动效与图标：motion、lucide-react
- 桌面封装：Electron

### 2.2 目录说明

| 路径 | 说明 |
| --- | --- |
| `src/main.tsx` | React 挂载入口 |
| `src/App.tsx` | 应用主页面与核心业务逻辑 |
| `src/types.ts` | 节点、连线、快捷键等核心类型定义 |
| `src/index.css` | 全局样式、主题变量与界面基础样式 |
| `electron/main.cjs` | Electron 主进程入口 |
| `docs/操作手册.md` | 面向使用者的详细操作说明 |

| `vite.config.ts` | Vite 构建配置与环境变量注入 |
| `package.json` | 依赖、脚本与 Electron 打包配置 |

### 2.3 架构特点

当前架构具备以下特点：

- 只有一个主页面，没有路由系统
- 没有独立后端服务或业务 API 层
- 没有 Redux、Zustand 等外部状态管理库
- 主要状态、交互和渲染都在 `App.tsx` 中集中维护

这意味着项目上手成本低，但随着功能增加，`App.tsx` 的维护复杂度会持续上升。

## 3. 核心数据模型

项目围绕两类核心对象展开：

### 3.1 节点 Node

节点是画布上的基础信息单元，主要包含：

- `id`：唯一标识
- `x / y`：画布坐标
- `text`：节点文本内容
- `style`：节点样式

当前节点样式包括：

- `default`：默认节点
- `text`：纯文本节点
- `note`：备注节点
- `warning`：警示节点

### 3.2 连线 Connection

连线表示节点之间的关系，主要包含：

- `id`：唯一标识
- `fromId`：起点节点 ID
- `toId`：终点节点 ID，可为空
- `text`：连线标签
- `style`：箭头样式
- `tempToPos`：未完成连接时的临时终点位置
- `curveBend / curveBendRatio`：曲线弯曲控制数据

当前连线样式包括：

- `forward`：正向箭头
- `backward`：反向箭头
- `both`：双向箭头
- `none`：无箭头

### 3.3 焦点机制

系统的交互核心不是传统表单，而是“焦点状态机”：

- 空焦点
- 节点焦点
- 连线焦点
- 节点编辑态
- 连线编辑态

大多数快捷键行为都依赖当前焦点类型变化，这是项目交互设计最关键的实现基础。

## 4. 核心功能模块

## 4.1 画布与视图控制

系统提供一个可交互的无限画布，用于承载节点与连线。

主要能力包括：

- 画布背景网格显示
- 鼠标拖拽平移画布
- 触控板双指平移
- `Ctrl/Cmd + 滚轮` 或捏合缩放
- 快捷键放大、缩小、重置缩放
- 在部分焦点切换场景下自动将目标对象移入可视区域

该模块决定用户能否高效浏览复杂关系图，是整个应用的基础能力。

## 4.2 节点管理

节点相关功能是项目最基础的编辑能力。

支持的功能包括：

- 在空焦点状态下快速创建节点
- 在当前节点下方创建新节点
- 点击节点选中
- 拖拽节点移动位置
- 多选状态下批量拖动节点
- 节点文本编辑
- 删除节点
- 节点样式切换

节点创建通常会自动进入编辑态，便于连续输入内容，提高键盘操作效率。

## 4.3 连线管理

连线用于描述节点之间的方向性关系或语义关联。

支持的功能包括：

- 从节点发起一条新连线
- 创建未完成连接的临时连线
- 在连线终点处创建目标节点并完成连接
- 将连线连接到已有节点
- 编辑连线文字标签
- 切换箭头样式
- 删除连线
- 拖拽起点、终点和弯曲控制点
- 将连线重新挂接到其他节点

连线既支持完整连接，也支持“待完成状态”，这让用户可以先表达关系，再补充目标对象。

## 4.4 搜索连接目标

当焦点在连线上时，系统支持通过搜索方式快速指定目标节点。

主要流程如下：

- 打开搜索面板
- 输入关键字过滤节点
- 使用键盘上下选择结果
- 通过回车、Tab 或鼠标点击完成连接

这个功能适合大图场景，可减少人工拖动连线造成的操作成本。

## 4.5 焦点导航与键盘优先编辑

本项目的重要特色是键盘优先。

支持的能力包括：

- 使用方向键在节点和连线之间切换焦点
- 使用快捷键快速创建节点和连线
- 使用快捷键进入编辑态
- 使用快捷键完成撤销和重做
- 使用快捷键切换节点样式和连线样式
- 在不同焦点状态下复用相同按键实现不同语义

例如 `Enter` 在不同状态下分别可能表示：

- 创建节点
- 从当前节点创建连线
- 完成连线并创建目标节点
- 跳转到已连接目标节点

这套设计提升了熟练用户的操作速度，但也要求文档和提示面板保持同步更新。

## 4.6 多选、框选与批量移动

系统支持对节点进行范围选择与批量移动。

主要能力包括：

- 在空白区域拖拽生成选择框
- 自动选中框内节点
- 单个选中时自动聚焦节点
- 多个选中时保留选择集合
- 拖动任意已选节点时整体移动整组节点

当前实现中，框选能力主要面向节点，普通连线不是主要框选对象。

## 4.7 文本编辑

系统区分对象焦点和文本编辑态。

编辑相关能力包括：

- 节点文本编辑
- 连线标签编辑
- 点击或快捷键进入编辑态
- `Enter`、`Esc` 或失焦结束编辑
- 编辑态下暂停大部分对象级快捷键，避免误操作

这使项目既能保持键盘编辑效率，又能避免文本输入时触发结构性操作。

## 4.8 历史记录

系统内置撤销与重做能力，用于保障编辑安全。

主要能力包括：

- 撤销上一步操作
- 恢复被撤销操作
- 顶部按钮触发
- 快捷键触发

历史记录覆盖节点、连线和部分视图状态变化，是保证可编辑体验的重要基础能力。

## 4.9 文件导入、导出与保存

项目支持将图结构保存为 JSON 文件，并再次加载。

具体能力包括：

- 从本地导入 JSON 文件
- 将当前图导出为 JSON 文件
- 在支持 File System Access API 的浏览器中直接保存到原文件
- 在不支持直接保存的环境中自动降级为下载文件
- 新建文件前尝试先保存当前内容

当前导入导出的内容不仅包含节点和连线，还包含部分视图和快捷键相关配置。

## 4.10 图片导出

系统支持将当前整张图导出为 PNG 图片。

该功能具备以下特点：

- 导出范围基于所有实际内容边界
- 不受当前窗口可见区域限制
- 会导出节点、连线、标签和箭头
- 会跟随当前主题影响背景和颜色表现
- 对超大内容进行尺寸限制，降低浏览器导出失败概率

这个功能适合分享方案图、流程关系图和脑图快照。

## 4.11 设置与个性化

系统提供设置面板用于管理显示和操作习惯。

当前支持：

- 浅色模式与深色模式切换
- 快捷键重绑定
- 快捷键冲突校验
- 本地保存主题设置
- 本地保存语言设置

快捷键配置允许用户根据自己的工作习惯调整操作方式，是项目差异化体验的一部分。

## 4.12 多语言支持

当前系统支持中英文界面切换。

主要特点：

- 可通过界面按钮切换语言
- 默认会结合浏览器语言或本地缓存进行初始化
- 语言选择会写入本地存储

## 4.13 Electron 桌面运行

项目除了 Web 形态外，还支持 Electron 桌面壳。

桌面版的作用主要是：

- 提供独立窗口运行体验
- 复用同一套前端页面
- 在开发模式下连接本地 Vite 服务
- 在生产模式下加载打包后的静态文件

当前 Electron 打包配置以 Windows 目录包为主。

## 6. 运行方式

### 6.1 Web 开发

常用命令：

```bash
npm install
npm run dev
```

默认使用 Vite 启动本地开发服务，端口为 `3000`。

### 6.2 Web 构建

```bash
npm run build
```

构建结果输出到 `dist` 目录，可用于静态部署。

### 6.3 Web 预览

```bash
npm run preview
```

### 6.4 Electron 开发

```bash
npm run dev
npm run electron:dev
```

Electron 会在开发模式下加载本地 `http://localhost:3000` 页面。

### 6.5 Electron 构建

```bash
npm run electron:build
```

当前配置会先执行前端构建，再执行 Electron 打包，输出目录为 `release`。

## 7. 部署与环境说明

### 7.1 静态部署

Vite 配置中使用了相对路径 `base: './'`，说明项目适合部署到：

- GitHub Pages
- 任意静态文件服务器
- 需要相对路径资源引用的离线场景

仓库中已存在 GitHub Actions 工作流用于 Pages 部署。

### 7.2 本地存储

当前本地持久化主要保存：

- 语言设置
- 主题设置

### 7.3 文件系统能力

在支持浏览器 File System Access API 的环境中，项目支持直接打开和保存本地文件。

在以下场景中会自动降级：

- iframe 环境
- 不支持 `showOpenFilePicker`
- 不支持 `showSaveFilePicker`

降级后的行为一般是使用文件选择或下载方式完成导入导出。

## 8. 当前实现边界与注意事项

从当前代码实现看，项目存在以下边界：

- 没有账号体系、权限体系或协作功能
- 没有云端存储或后端同步能力
- 没有多页面、多项目管理或工作区概念
- 没有独立服务层，所有主要逻辑集中在前端
- 没有正式测试脚本，`lint` 当前仅执行 TypeScript 类型检查

此外，还存在一些工程层面的现象：

- 依赖中存在 `@google/genai`、`express` 等包，但当前核心功能未看到明确业务使用链路
- Vite 配置注入了 `GEMINI_API_KEY`，更像预留能力或历史遗留配置
- 代码中包含性能调试上报逻辑，说明项目对大图性能做过专项排查

基于当前功能，项目更适合以下场景：

- 关系图梳理

## 10. 后续维护建议

如果后续继续演进，建议优先关注以下方向：

- 将 `App.tsx` 拆分为画布渲染、快捷键系统、文件读写、历史记录、设置面板等子模块
- 为导入导出、图片导出、快捷键重绑等关键功能补充自动化测试
- 补充正式的开发、部署和发布文档
- 明确 Electron、GitHub Pages、iframe 发布形态之间的主次关系
- 清理未使用依赖与遗留环境变量，减少理解成本

## 11. 总结

`SysMind` 当前是一个以单页前端应用为核心的系统图编辑工具，核心价值在于：

- 节点与连线表达能力清晰
- 键盘优先的编辑效率较高
- 文件导入导出和图片导出较完整
- 支持语言、主题和快捷键个性化
- 可以同时覆盖浏览器与桌面运行场景

如果把它作为内部工具、轻量关系图工具或可视化编辑器基础版本来看，当前功能已经比较完整；如果要继续产品化，下一阶段重点会落在模块拆分、质量保障和发布说明完善上。
